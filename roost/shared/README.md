# Shared algorithms and fixtures

Roost implements a handful of algorithms twice — in Swift (`ios/RoostKit`) and TypeScript (`web/src/core`) — and the server implements access computation in Go. To keep them identical, **this file is the spec** and `fixtures/*.json` are the acceptance tests every implementation runs.

## 1. Text normalization (`normalize`)

1. Lowercase; Unicode NFD and drop combining marks (`jalapeño` → `jalapeno`).
2. `&` → ` and `; delete `'` and `’`.
3. Replace every run of characters outside `[a-z0-9%]` with one space; trim.

Tokens = normalized string split on spaces.

## 2. Grocery line parsing (`parseGroceryLine`)

Input: one raw line. Output: `{ name, quantity|null, unit|null }`. `name` keeps the user's casing with surrounding whitespace/punctuation trimmed and the first letter upper-cased.

Work on the raw line split by whitespace (after splitting `2x`→`2 x`… see below):
1. **Trailing multiplier**: `x2`, `×2`, `x 2`, `× 2`, `(2)` at the end → quantity, removed.
2. **Leading quantity** (only if no trailing multiplier):
   - number forms: `2`, `2.5`, `.5`, `1/2`, `1 1/2`, `½ ¼ ¾ ⅓ ⅔ ⅛`, `1½`, a number immediately followed by `x` (`2x`), or a number glued to a unit (`2lb`, `6-pack`);
   - words: `a`/`an` = 1, `a couple` / `couple` = 2, `one`…`twelve`, `half` = 0.5. A following `of` is dropped (`a couple of avocados`).
   - A token like `2%` is **not** a quantity.
3. **Unit**: if the token after the quantity (or the first token when the quantity was `a/an` or absent… only with a quantity) is a unit word, consume it, then drop a following `of`. Units and canonical forms:

   `lb lbs pound pounds → lb` · `oz ounce ounces → oz` · `g gram grams → g` · `kg kgs kilogram(s) → kg` · `ml → ml` · `l liter(s) litre(s) → l` · `gal gallon(s) → gal` · `qt quart(s) → qt` · `pt pint(s) → pt` · `cup(s) → cup` · `dozen doz → dozen` · `pack(s) pk pkg package(s) → pack` · `box(es) → box` · `bag(s) → bag` · `can(s) → can` · `jar(s) → jar` · `bottle(s) → bottle` · `bunch(es) → bunch` · `head(s) → head` · `loaf loaves → loaf` · `carton(s) → carton` · `container(s) → container` · `roll(s) → roll` · `bar(s) → bar` · `stick(s) → stick` · `piece(s) pc pcs → piece` · `ct count → ct` · `case(s) → case` · `tub(s) → tub` · `bunch → bunch`

   `dozen` with no number (`dozen eggs`) → quantity 1, unit dozen.
4. If removing the unit leaves an empty name, the unit word *is* the name (`6 rolls` → name `Rolls`, qty 6, unit null).

## 3. Categorization (`categorize`)

Index: every taxonomy term is normalized (§1) and stored → category. Learned household terms (exact normalized name → category) are checked first.

For tokens `t[0..n)`:
1. **Learned**: the normalized full name, or its singular form (§3.1 applied to the last token), is in the learned map → that category.
2. **Phrase match**: for every n-gram (length 4 → 1), test candidate forms: the n-gram as-is, then with its **last token** replaced by each singular variant. Exact forms are tried before singular forms. Each hit records `(length, endIndex, exactness)`. Winner: longest; ties → greatest `endIndex` (the head noun is usually last: "chicken **broth**"); then exact before singular.
3. **Modifier**: if no phrase hit, a token equal to a modifier key (`frozen`, `canned`, `boxed`) → its category. A modifier also **overrides** a phrase hit whose category is `produce`, `meat`, `bakery` or `dairy` (`frozen strawberries` → Frozen, `canned salmon` → Pantry).
4. Otherwise `other`.

Return `{ category, source }` with source `learned` | `dictionary` | `none`.

### 3.1 Singular variants (in order, deduplicated, excluding the original)
- ends `ies` (len > 4) → `…y`
- ends `oes` → `…o`
- ends `ves` → `…f` and `…fe`
- ends `ses`, `xes`, `zes`, `ches`, `shes` → drop `es`
- ends `s` and not `ss`, `us`, `is` → drop `s`

### 3.2 Merge key
`mergeKey(name)` = normalized name with each token's first singular variant applied (or itself). Adding an item whose merge key equals an existing **unchecked** item merges: if both units are equal (or both null) quantities add (null counts as 1); otherwise the new item is added separately. Matching a **checked** item un-checks it and replaces its quantity/unit.

## 4. Quick-add parsing (`parseQuickAdd(text, now, tz, mode)`)

`mode` is `event` or `task`. `now` is a local wall time in `tz`. Output:

```
{ title, date: "YYYY-MM-DD"|null, time: "HH:mm"|null, endDate, endTime,
  allDay, rrule|null, mentions: [string], driver: string|null,
  tag: string|null, priority: 0-3, reminders: [minutes] }
```

Tokens are removed from the title as they are recognized, in this order:
1. `driver:Name` → driver. `@Name` → mention (word chars, keeps case). `#Tag` → tag (first one wins; `#Two_Words` → "Two Words").
2. Priority: `!!!` → 3, `!!` → 2, standalone `!` → 1, `!high` 3, `!med`/`!medium` 2, `!low` 1.
3. Reminders: `remind [me] N(m|min|mins|minutes|h|hr|hrs|hour|hours|d|day|days|w|week|weeks) [before]` → minutes. Several allowed.
4. Recurrence:
   - `daily` / `every day` → `FREQ=DAILY`; `every other day` → `FREQ=DAILY;INTERVAL=2`; `every N days` → `INTERVAL=N`.
   - `weekdays` / `every weekday` → `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR`; `weekends` / `every weekend` → `FREQ=WEEKLY;BYDAY=SA,SU`.
   - `weekly` / `every week` → `FREQ=WEEKLY`; `every other week` / `biweekly` → `FREQ=WEEKLY;INTERVAL=2`; `every N weeks` → `INTERVAL=N`.
   - `every <weekday list>` (e.g. `every tue and thu`, `every mon, wed, fri`, `every other tuesday`) → `FREQ=WEEKLY[;INTERVAL=2];BYDAY=…` in Monday-first order.
   - Ordinal weekdays (`every 1st and 3rd mon`, `every first tuesday`, `every last friday`; ordinals `1st…4th`, `first…fourth`, `last`) → `FREQ=MONTHLY;BYDAY=1MO,3MO` (ordinal order as written).
   - `monthly` / `every month` → `FREQ=MONTHLY`; `yearly` / `annually` / `every year` → `FREQ=YEARLY`.
   - If a weekday list is given and no explicit date, the date is the first matching day on/after today (honoring ordinals).
5. Dates (first match wins): `today`; `tonight` (today, default time 18:00 if no time given); `tomorrow`/`tmrw`/`tmw`; `this weekend` → coming Saturday (today if Saturday); `next week` → Monday of next week; `in N day(s)/week(s)`; `next <weekday>` → the first such day after today, plus 7 days if it falls in the current Monday–Sunday week; `[on|this] <weekday>` → today if it matches, else next; month-name dates `dec 3`, `december 3rd`, `3 dec`; numeric `12/3`, `12/3/2026`, `12/3/26`; ISO `2026-12-03`. A month/day without a year that is already past this year rolls to next year. A `due` immediately before a date is removed.
6. Times: `noon` 12:00, `midnight` 00:00; `4pm`, `4 pm`, `4:30pm`, `4:30 p.m.`, `16:00`; `at 5` (bare hour after `at`: 1–7 → PM, 8–11 → AM, 12 → noon). Ranges: `4-5pm`, `4–5:30pm`, `4pm-5pm`, `from 3 to 4:30pm`, `3pm to 4pm`, `10am-2pm`. A range's start inherits the end's meridiem unless that would put start after end (then AM). `for N h|hr|hours|min|minutes` sets the end from the start.
7. Events with a time but no end get 60 minutes. Events with no time are all-day. Tasks never get an end.
8. Title: remaining words, whitespace collapsed, trailing/leading connector words (`at on from by due for in every the`) trimmed, first letter upper-cased.

## 5. Recurrence expansion (`expand(event, rangeStart, rangeEnd)`)

- Expansion runs in **wall-clock time** in the event's `tz` (all-day: dates only), using the RFC 5545 subset in DESIGN §4. Each candidate wall time is converted to an instant in `tz`; the occurrence is returned if `[start, start+duration)` overlaps `[rangeStart, rangeEnd)` (instants). Zero-length events overlap if `rangeStart <= start < rangeEnd`.
- `DTSTART` is always the first occurrence, even when it doesn't match the BYxxx parts, and it counts toward `COUNT` (RFC 5545 §3.8.5.3 — what Apple and Google Calendar do). Fixtures are generated with python-dateutil plus that adjustment (`tools/gen_recurrence.py`).
- `COUNT` counts occurrences from DTSTART regardless of the range. `UNTIL` is inclusive; a date-only `UNTIL` means end of that local day; `UNTIL=…Z` is a UTC instant.
- Invalid dates (Feb 30, the 31st in 30-day months) are skipped, not clamped.
- `exdates` are occurrence keys (`YYYY-MM-DDTHH:mm` or `YYYY-MM-DD`) and are removed.
- Output: occurrence keys in ascending order. Times that fall in a DST gap are not used in fixtures.
- Safety: stop after 50,000 candidate iterations (a daily event that started 20 years ago is ~7,300).

## 6. Day layout (`layoutDay(items)`)

Input: `[{id, start, end}]` in minutes from midnight (end > start; zero-length treated as 15 min). Sort by start asc, then end desc, then id. Sweep, building **clusters** of transitively overlapping items (a new item joins the cluster if its start < the cluster's max end). Within a cluster, put each item in the lowest-index column whose last item ends ≤ its start. Every item in a cluster gets `cols = number of columns used by the cluster`. Output `{id: {col, cols}}`.

## 7. Access (`effectiveLevel(resourceKind, resourceSubkind, role, sharing, isResourceOwner)`)

Levels: `none` < `busy` < `view` < `edit`.
1. `isResourceOwner` → `edit`.
2. `sharing.people[membershipId]` if present.
3. `sharing.roles[role]` if present.
4. The kind default table in DESIGN §3.2.
5. `busy` is only meaningful for calendars; for lists and info cards it is treated as `none`.

## 8. Task recurrence (`nextDue(task, completedAtLocal)`)

Given a task with `due` (`YYYY-MM-DD` or `YYYY-MM-DDTHH:mm`) and an `rrule`, return the first occurrence strictly after `due`; while that occurrence's **date** is ≤ the completion date, advance again. Returns null when the rule is exhausted (COUNT/UNTIL). The completed instance is kept as a separate completed task.
